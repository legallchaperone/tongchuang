# 需求梳理：一起上课（R-030）

> 2026-11-10。**已拍板并在 v1.11.0 上线第一版**，决定见文末“拍板结果”。起因：想和同学一起学 Stanford CS336（Language Modeling from Scratch），一起学更有动力。本文把原始想法拆成能拍板的问题，给出推荐做法和第一版范围。登记在 [需求池](../BACKLOG.md) R-030。

## 原始想法

1. 提交“一起上课”申请：把想上的课的所有资料打包成 zip；开发者用 AI 把它整理成课表：每周进度、project、hw、考试。上课时间不限，只约束要交的东西。
2. 同窗上出现这门课的页面，大家报名一起学、跟进度、按时交作业；交了之后 AI 批改并给反馈；能看到彼此的进度。也许接一个 autograder。

## 先说结论

原始想法里其实混着三件事，应该分开设计、分开上线：

| | 是什么 | 谁做 | 第一版怎么做 |
|---|---|---|---|
| **课程**（课表模板） | 一门课按“第几周”排好的里程碑：读什么、交什么、交付物的格式 | 开发者用 AI 整理，人工审核 | 和 `lib/changelog.json` 一样，**一个 JSON 文件放进仓库**，不做后台 |
| **一期**（班级） | 某几个人从某一天开始一起学某门课，课表上的“第 N 周”换算成具体截止时间 | 发起人创建，同窗用邀请码加入 | 新做，挂在自习室旁边 |
| **提交与反馈** | 每个里程碑交一次：链接、测试结果、报告；AI 给反馈；同期的人看得到进度 | 学习者交，AI 改 | 先做“交了没有 + 测试通过几个 + AI 读报告给反馈”，**不做服务端跑代码** |

最重要的一点：**课程和“一期”必须分开。** 同一份 CS336 课表，你们 12 月开一期，别人 3 月再开一期，课表不用重做；课表只写“第 3 周周日交 A1 第一部分”，开课日期定了才算出具体时间。

## 一、先看别人怎么做的

| 参考 | 和我们相关的做法 | 可以借 |
|---|---|---|
| **Datawhale 组队学习** | 每月开一期；一个学习内容拆成若干 Task，每个 Task 有截止日；按时交“打卡链接”（笔记/代码），没按时交会被移出；有助教 | 按期开课、任务有截止、**打卡 = 交链接**，门槛低 |
| **DataTalksClub Zoomcamp**（开源的 [course-management-platform](https://github.com/DataTalksClub/course-management-platform)） | 课程材料随时可看，但作业表单只在这一期开放、**截止后关闭**、截止前可以改；作业有分、有排行榜；期末项目由 3 个同学互评 | 截止前可改、截止后关闭；排行榜；**同学互评**代替一部分 AI 批改 |
| **GitHub Classroom** | 每人一个仓库，push 之后 GitHub Actions 自动跑测试，结果回传 | 以后接 autograder 的方式：**在学习者自己的仓库里跑**，我们只收结果 |
| **Gradescope** | 学校用的 autograder：老师提供 Docker 镜像，学生提交后在镜像里跑，输出 `results.json` | 只作参考格式；它是给学校的，不能接给个人用 |
| **CS336 官方** | 每个作业的仓库自带 `pytest` 测试；A1/A2 等有公开排行榜（往 leaderboard 仓库提 PR）；自学的人要自己租 GPU | **测试已经现成**，不用我们写；排行榜可以照搬“报指标”的形式 |
| **同窗自己** | 已经有：科目、待办、专注记录、自习室、动态、评论、点赞 | 报名一门课 = 自动多一个科目；专注时长直接算进课程进度 |

## 二、CS336 这门课本身的特点（决定了很多设计）

以 2025 春季版为准（2026 春季版以官网为准，结构大致相同）：

- 5 个作业，每个 2–3 周，量很大：A1 Basics（BPE 分词器、Transformer、AdamW、在 TinyStories/OpenWebText 上训练）、A2 Systems（性能分析、Triton 写 FlashAttention2、分布式训练）、A3 Scaling（拟合 scaling law）、A4 Data（清洗 Common Crawl）、A5 Alignment（SFT、GRPO）。
- **每个作业的仓库自带测试**（`uv run pytest`），通过多少个测试是现成的客观指标。
- **很多部分要 GPU**：A1 小模型在笔记本上能跑，OpenWebText 那部分和 A2、A5 基本要租 NVIDIA GPU。我们的服务器不可能替大家跑。
- A3 当年用的是斯坦福内部提供的训练 API，校外的人可能用不了，课表里要标“自学替代方案”。
- 交付物 = 代码 + 一份写作报告（问答题、曲线、实验结论）。报告是 AI 最能帮上忙的地方。

结论：**“autograder”在第一版里 = 学习者在自己机器上跑官方测试，把结果贴上来**；服务端只做 AI 读报告、读代码片段给反馈。

## 三、需要拍板的问题（附推荐答案）

### 1. 叫什么

“同窗”是同学，这个功能是“一起修一门课”。候选：

- **同修**（推荐）：“同窗”+“修课”，两个字，和产品名同一个调子；“我们在同修 CS336”。
- **共学**：直白，但很多平台在用。
- **结伴上课**：最口语，按钮上偏长。

下文都叫“同修”。

### 2. 谁能看到、谁能加入

现在同窗是封闭的：只有同一个自习室的人能看到彼此。

- **推荐**：一期同修 = 一个特殊的自习室（或绑定一个自习室），**用邀请码加入**，人数沿用 12 人上限。课程页（课表本身）所有登录用户都能看，方便别人看了想自己开一期。
- 不推荐第一版就做“公开招募、陌生人报名”：要处理审核、骚扰、广场列表，和同窗现在的定位不一样。以后想做可以单独开需求。

### 3. 申请开课的流程

原始想法是“上传 zip → 开发者用 AI 做课表”。

- **推荐第一版**：不做上传功能。申请 = 一个表单：课程名、官网链接、想什么时候开始、每周大概能投入几小时、要不要考试；资料按链接给（CS336 的资料本来就全在官网和 GitHub 上）。开发者整理成 JSON 课表，提交到仓库，发版上线。
- **为什么不收 zip**：大部分公开课资料都在线上，链接更好维护；zip 里可能有版权材料（教材 PDF、别校的未公开作业），我们存了就是在替别人分发；Supabase 存储也有容量和费用。
- **以后**：确实有只能离线拿到的资料时，再加“上传到私有存储、只有开发者能看、整理完删除”。
- 课表**不重新托管课程材料**，只放链接和我们自己写的说明（第几周看哪几讲、作业拆成哪几段、交什么）。

### 4. 课表长什么样

AI 整理课表时要产出这些东西（也就是 JSON 的字段）：

- 课程：名称、官网、简介、总周数、每周建议投入时长、前置要求、**算力要求**（例如“A2 需要 NVIDIA GPU，约 X 小时”）。
- 每周：要看的讲次（链接）、建议阅读。
- 里程碑（要交的东西）：在第几周第几天截止、类型（作业 / 项目 / 小测 / 考试）、交付物要求（链接、测试结果、报告、指标）、评分要点（给 AI 批改用）、**是否能在校外完成**及替代方案。
- **大作业拆成小里程碑**：CS336 一个作业 2–3 周，只在最后交一次，前两周没人知道你落没落下。推荐每周至少一个检查点，例如 A1 拆成“BPE 分词器通过测试 → Transformer 各模块通过测试 → 训练完 TinyStories 交曲线 → 报告”。这一条对“一起学更有动力”最关键。

### 5. 截止时间按谁的时区

同窗一直强调“每个人的今天按自己的时间算”。截止时间有两种选法：

- **推荐：按每个人自己时区的那天 23:59**（例如“第 3 周周日”对上海的人是上海时间周日晚上、对纽约的人是纽约时间周日晚上）。和连续天数的规则一致，跨时区的同学都公平。
- 另一种：全期统一一个时刻（比如北京时间周日 23:59）。简单，但对时差大的人不公平。

### 6. 迟交、落后、退出

“定时交”只有在有后果的时候才有约束力，但同窗是朋友之间的产品，后果不能太重。推荐：

- 截止前可以反复改；**截止后还能交，但标“迟交”**，不关闭（和 Zoomcamp 不同：他们有证书要发，我们没有）。
- 每人每期有 **3 张“缓交卡”**，用了就把某个里程碑延后 3 天且不算迟交（生病、考试周）。
- 进度面板上落后的人**不点名批评**，只显示“还差 1 个检查点”；截止前 24 小时提醒还没交的人自己。
- 可以随时退出；退出后记录保留，不再出现在这一期的进度面板上。
- 是否做“迟交太多被移出”（Datawhale 的做法）：**第一版不做**，人少的时候靠朋友之间的情面就够了。

### 7. 交什么、怎么批

分三层，第一版只做前两层：

1. **客观结果（学习者自报）**：粘贴 `pytest` 输出的最后一行（例如 `46 passed, 2 failed`），系统解析成“通过 46/48”；需要指标的里程碑填数字（例如验证集 loss）。可以附 GitHub 仓库链接 + commit。
2. **AI 反馈**：上传报告（PDF/Markdown）或贴代码片段，AI 按课表里的“评分要点”给反馈：哪题答得不完整、曲线是否说明了问题、建议补什么实验。**不打分、只给反馈**，避免大家去刷 AI 的分。
3. **以后再做**：
   - **自动跑测试**：提供一个 GitHub Actions 模板，学习者放进自己的仓库，push 后在 GitHub 的机器上跑 CPU 能跑的测试，结果回传到同窗（GitHub Classroom 的做法）。GPU 部分永远自报。
   - **同学互评**：截止后随机分配 1–2 份同期的作业互相看，写一句评价（Zoomcamp 的做法）。人少时这比 AI 更有用。
   - **排行榜**：只对有客观指标的里程碑开，例如 A1 的 OpenWebText loss，照搬 CS336 官方排行榜的形式。

### 8. 能看到别人的什么（防抄）

CS336 选课的学生不能公开答案；我们这里都是自学，但一起学最怕一个人做完、其他人直接看他的。推荐：

- 截止前：同期的人只能看到**你交没交、测试通过几个、花了多少时间**，看不到你的代码链接、报告和 AI 反馈。
- 截止后（或自己也交了之后）：可以互相看，方便讨论。
- 每个人可以自己选“截止后也不公开”。

### 9. 进度怎么显示（动力从哪来）

这是这个需求的根本目的，要和同窗已有的东西接起来，而不是另做一个系统：

- **报名后自动建一个科目**（例如“CS336”），专注时选它，时长就算进这门课。课程页能看到“这周大家在 CS336 上各学了多久”。
- **每个检查点自动出现在待办里**，带截止日，可以直接“从待办开始专注”。
- **进度面板**：一张“人 × 里程碑”的格子表，交了的格子点亮（像素风，像热力图）；每人一行显示本周时长。
- **书桌**：专注时选了课程科目，书桌上显示“在学 CS336 · A1 分词器”。
- **动态**：交了作业发一条动态（“小明交了 A1 第一部分 · 通过 48/48”），可以点赞、评论，沿用 R-027 的可见范围。
- **每周小结**：周一给这一期发一张“上周大家交了什么、学了多久”的分享图（沿用分享图组件）。

### 10. AI 的成本和谁来付

- 课表整理：一门课一次，开发者手动用 AI 做，成本可忽略。
- 作业反馈：每次提交调一次模型。按 CS336 一期 12 人、约 15 个检查点、每人平均改 2 次算，一期大约 360 次调用。需要决定：**开发者付**（推荐，第一版人少），还是让学习者填自己的 API key。
- 需要加一个服务端接口（现在全是前端直连 Supabase）：用 Vercel 的 API route 或 Supabase Edge Function 调模型，key 不能放前端。每人每个里程碑限制次数（例如 5 次），防止滥用。

## 四、第一版范围（推荐）

目标：**你们几个人能在 12 月开始一起学 CS336。**

**做：**

1. 仓库里放一份 CS336 课表 JSON（开发者用 AI 根据官网整理、人工审核），包括拆好的周检查点。
2. 课程页：简介、算力要求、按周的课表、每个里程碑的要求。
3. 开一期：选课程、选开课日期、生成邀请码；同窗用邀请码加入。加入后自动建科目、把检查点放进待办。
4. 提交：每个里程碑一个提交框（链接 + 测试输出 + 指标 + 报告/说明），截止前可改，截止后标迟交；3 张缓交卡。
5. 进度面板：人 × 里程碑格子 + 本周时长；截止前对没交的人提醒。
6. AI 反馈：提交后点“请 AI 看看”，按评分要点给文字反馈，只自己可见（截止后可选公开）。
7. 动态里出现“交了作业”。

**不做（以后再说）：** 上传 zip、公开招募、服务端跑测试、GitHub Actions 自动评测、同学互评、排行榜、AI 打分、证书。

## 五、可能要改的数据结构（草稿）

只是为了估工作量，实现时再细化：

- 课表：`lib/courses/cs336.json`（不进数据库，和更新日志一样随版本发布）。
- `cohorts`：一期，`course_id`、`room_id`、`starts_on`、创建人。
- `cohort_members`：谁在哪一期、`subject_id`（自动建的科目）、剩余缓交卡、加入/退出时间。
- `submissions`：`cohort_id`、`user_id`、`milestone_id`、链接、测试通过数/总数、指标、报告文件、提交时间、是否用了缓交卡。
- `feedback`：AI 反馈内容、对应哪次提交、可见范围。
- 行级权限：同一期的人能看到彼此的“交没交、通过几个”；链接、报告、反馈在截止前只有本人能看。

## 拍板结果（2026-11-10）

| 问题 | 决定 |
|---|---|
| 名字 | **同修** |
| 截止时间 | **地球上最晚的时区（AoE，UTC-12）**：某天截止 = 那一天在地球上所有地方都过完，即次日 12:00 UTC。页面同时显示“你这里是几点” |
| 迟交 | 截止后还能交，标“迟交”；每人每期 3 张缓交卡，一张晚 3 天；不踢人 |
| 能不能看别人交的内容 | 截止前只看得到交没交、测试数；截止后或自己也交了同一步之后能看；可以选只给自己看 |
| 开课申请 / zip | 不做。课程由开发者整理成 `lib/courses/*.ts`，随版本发布 |
| AI 反馈 | 不接 API。学习者勾“请开发者帮我看看”，开发者在 `/tongxiu/staff` 复制提示词交给 Claude，把反馈贴回来，对方收到提醒 |

实现位置：`lib/courses/`（课表）、`lib/tongxiu.ts`（截止时间、进度、pytest 解析、给 Claude 的提示词）、`app/(main)/tongxiu/`（页面）、`supabase/schema.sql` 的 R-030 一节（表和行级权限）。

## 六、作业改成 marimo 笔记本？（待定）

起因：molab（marimo 的云端笔记本）目前免费提供 RTX Pro 6000（96GB，Blackwell）；单卡，一次最长 12 小时，空闲 90 分钟自动关机（据 marimo 官方博客，公开预览期间，条款可能变）。

**建议：不把作业本身改写成笔记本，而是给每个作业配一个 molab“启动器”笔记本。**

不建议整份改写的原因：

- CS336 的作业是一个 Python 包：分词器、模型、优化器、训练脚本分在多个文件里，测试通过 `tests/adapters.py` 接进来。改成笔记本要么把代码塞进单元格（测试接不上），要么重新组织（和官方说明、测试对不上）。
- 课程每年更新，改写过的版本要跟着重做。
- 官方仓库的许可没有查到，改写后再分发需要先确认。

启动器笔记本（每个作业一个，几十行）做这些事：

1. 克隆学习者自己 fork 的仓库（或 `git pull`），`uv sync` 装依赖；检查 GPU 和 PyTorch / Triton 版本是否支持 Blackwell。
2. 一个按钮跑官方测试，显示结果，最后一行可以直接复制进同修的提交框。
3. 跑训练脚本，用 marimo 的图表实时画 loss；定期存 checkpoint，被关机后能接着跑。
4. 可选：一些交互式的小实验（看 BPE 合并过程、注意力图），这部分适合笔记本。

代码还是在自己的编辑器里写、push 到 GitHub；GPU 的活在 molab 上跑。同修的课表里给需要 GPU 的阶段加“在 molab 打开”链接即可，不用改同修本身。
