提出：2026-11-03（调研中发现的现有缺陷）

- 现状：计时状态只存在当前浏览器里。在手机上开始专注后，电脑上的页面不知道，两边可能各算一份时长。

## v1.4 留下的已知问题（以后顺手修）

- 状态和收工的两个开关（开始专注时清除状态、动态里显示状态）、倒计时上次的时长、科目合并的指向表都只存在当前浏览器里，换设备不同步。
- 科目表不在实时同步里：同窗要刷新后才看到被合并/删除的科目消失。
- 数据库没有“同名科目”唯一约束，去重只在前端做。
- 分享图的热力图分档阈值和颜色是从热力图组件复制过去的，以后改要两处一起改。
- 收工里“明天先做什么”同自习室可见（输入框已写明）。凌晨 5 点前收工算前一天。

## v1.11 留下的已知问题（以后顺手修）

- 同修的星星和完成还没进动态，只有页面开着时弹提醒。
- 课程只能由开发者写进 `lib/courses/`，改了里程碑的 id 会让已经交的作业对不上，改之前先看有没有人在修。
- “迟交”看的是数据库记的第一次提交时间和提交里存的截止时间；截止时间由前端算好写入，同修是朋友之间用的，没有在数据库里再校验。
- 开发者在 Supabase SQL Editor 里手动加：`insert into public.staff(user_id) select id from auth.users where email = '...'`。
- 星星对应的测试名是照官方仓库 2026 春季版核对的；课程仓库更新后要重新核对（每颗星至少要能对上一个测试，否则永远亮不了）。
- 上报命令需要 macOS / Linux 的终端（Windows 用 WSL）。还没做“push 到 GitHub 自动上报”（GitHub Actions），需要 GPU 的测试在 Actions 上也跑不了。

## v1.5 留下的已知问题（以后顺手修）

- 主页的累计时长和徽章只按最近约 400 天的记录算。

## 已确认的行为（回答过的问题，备查）

- **A 和 B 一个自习室、B 和 C 一个自习室，A 给 B 的记录点赞或评论，C 看得到吗？** 从 v1.10.2 起看不到（R-027，像朋友圈）。记录主人看得到全部；其他人只看得到和自己有共同自习室的人点的赞、写的评论。留言板暂时没改：B 的同窗都能看到 B 留言板上所有便利贴。（2026-11-06）

- **加入了多个自习室，专注状态是否每个自习室都能看到？** 能。专注状态记在“人”身上，不属于某个自习室；你所在的每个自习室都会显示你的书桌和计时，学习记录也会出现在每个自习室的动态里。（2026-11-03 对照代码确认）
